# Standalone Korean Wikipedia search

This component is separate from the editor and teacher environments. It uses no
GPU, embedding model, scorer, or live search service. `LocalWikiSearch.search`
tokenizes a query with local Kiwi and returns up to three local BM25 passages,
including `title`, `section`, `text`, `passage_id`, article URL, revision URL, and
license metadata. Empty or out-of-vocabulary queries return an empty list.

Use an isolated venv with `wiki_requirements.txt`; the RFT Python environment is
unchanged. Artifacts default to
`verak/v4/outputs/scale2/search` in the main checkout and are not committed.

```sh
python -m verak.v4.wiki_build download
python -m verak.v4.wiki_build extract
python -m verak.v4.wiki_build tokenize
python -m verak.v4.wiki_build index
python -m verak.v4.wiki_build search --query '지구 온난화 해수면 상승'
```

`download` selects the latest **completed** aggregate `pages-articles.xml.bz2`
listed by the official Wikimedia dump service. The date, metadata job, source
URL, byte size, official SHA1 and local SHA256 are saved. It resumes a partial
download and refuses to use a file whose byte size or SHA1 differs. Download
bandwidth is capped at 8 MiB/s; all commands use CPU affinity 116–119, nice 19,
idle I/O priority and one BLAS thread. Kiwi uses two CPU workers.

Extraction streams XML into SQLite. Main-namespace prose is retained; redirects,
disambiguation pages and list pages are excluded using XML fields and explicit
title/template/category markers. This is a recorded deterministic filter, not
a claim of perfect page classification. Wiki templates, tables, bullet lists,
references and reference/navigation sections are removed without online template
expansion. Paragraphs retain their section hierarchy. The stable ID includes
dump date, page ID, revision ID and a hash of section, ordinal and paragraph text.
Extraction and tokenization resume from transactionally saved progress.

Kiwi content morphemes from title, section and body form the lexical index.
BM25 uses the Lucene formula, `k1=1.5`, `b=0.75`; its saved arrays are memory-mapped
for retrieval. There is no query-dependent tuning or reranking.

Wikipedia text is used under [CC BY-SA 4.0](https://creativecommons.org/licenses/by-sa/4.0/).
Article attribution links and revision links are preserved, together with a
notice that markup was removed. See [Wikimedia's licensing terms](https://foundation.wikimedia.org/wiki/Policy:Terms_of_Use#7._Licensing_of_Content)
and the [official Korean dump directory](https://dumps.wikimedia.org/kowiki/).
A future INSERT based on a retrieved passage must paraphrase and cite both its
title and passage ID. `insertion_citation_contract` supplies that reference
metadata; it is not connected to an editor and does not claim to verify semantic
paraphrasing. No SEARCH-derived INSERT is generated by this task.

## Separate, authorized offline evaluation

`wiki_eval prepare` freezes 50 existing `needs_search=yes` feedback items from
50 train sources (17 argumentative, 17 explanatory, 16 emotional), without test
sources or test-question overlap. The feedback is LLM-written, not human gold.
`wiki_eval run` has a separate durable SQLite reservation ledger with a $2 cap,
Sol low, output limits 384 for short queries and 640 for judgments, at most 110
calls including transport retries, and one in-flight request. Completed and
failed outcomes are retained rather than silently regenerated.

Before dispatch, `eval/paid_authorization.json` must record the independently
approved v4.2 environment contract path and its SHA256. This is a decision-order
condition, not a dependency on the editor smoke-test result. The sample, prompts,
index contract, model, limits and pricing rates are frozen in `eval/contract.json`.

Normal SEARCH sends nothing outside the server. The explicitly authorized Sol
evaluation is a separate API exception: it sends each fixed feedback item,
question, at most three located source sentences (always fewer than all source
sentences; at most 1,500 characters), and the exact top-three passages. Complete
student essays are not request fields. The judge returns `yes`, `partly` or `no`
for whether any retrieved passage supports a suitable fact/example; it does not
write a revision. Reports disclose this boundary and give rates by genre.
Budget stops preserve partly dispatched items and report all unjudged outcomes
as unknown, with rates against the planned sample and separate judgment-only
rates in the metrics file.
