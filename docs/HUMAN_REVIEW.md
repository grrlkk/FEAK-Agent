# 현재 파일럿의 사람 블라인드 평가

`scripts/run_pilot_review.py`는 저장된 파일럿 후보를 사람이 네 기준으로 평가하는 로컬 웹 도구다.
Kanana나 GPT를 실행하지 않으며 API 키도 필요 없다. 기존 에이전트와 과거 웹 화면의 동작은 바꾸지 않는다.

## 준비와 실행

```bash
conda activate feak_agent

# 현재 run_pilot.py 출력 폴더를 사용한다. 새 study-dir만 허용한다.
python scripts/run_pilot_review.py prepare \
  --run-dir experiments/results/rv_pilot_real \
  --study-dir experiments/results/human_review_study \
  --raters 2 --seed 20260929

python scripts/run_pilot_review.py serve \
  --study-dir experiments/results/human_review_study --port 8766

# 별도 터미널에서 평가자별 비공개 접속 링크를 확인한다.
python scripts/run_pilot_review.py links \
  --study-dir experiments/results/human_review_study
```

기본 주소는 `http://127.0.0.1:8766`이다. 평가자에게는 그 사람의 링크 하나만 전달한다.
URL의 `#token=...` 값은 참여 코드로 직접 입력해도 된다. 로그인 후 주소에서 코드를 제거하며,
인증 정보는 해당 브라우저 탭의 sessionStorage에 보관한다. 새로고침 후 이어서 평가할 수 있다.
다른 탭·브라우저에서는 같은 링크로 다시 접속한다.

원격 서버라면 SSH 포트 전달 등으로 로컬에 접속한 후, `links --base-url`에 실제 평가자의
접속 주소를 지정할 수 있다. 기본 서버는 루프백 전용이다. 이 도구는 로컬/신뢰된 연결용이며
인터넷 공개 서비스용 계정 관리·TLS 서버는 포함하지 않는다.

## 평가 흐름

1. 배정된 항목의 문항, 수정 목표, 원문과 수정문을 읽는다. 보존 조건은 펼쳐서 확인할 수 있다.
2. 목표 달성·수정 필요성·의미 보존·전체 글의 이익을 각각 PASS/FAIL/UNCERTAIN으로 판단한다.
3. 각 판정의 근거를 적는다. 기본 선택값이나 자동 추천 판정은 없다.
4. 입력 후 약 0.9초가 지나면 임시 저장된다. `임시 저장` 버튼으로도 저장할 수 있다.
5. 네 판정과 비어 있지 않은 근거를 모두 입력한 뒤 `저장하고 다음`으로 평가를 완료한다.
6. `나중에 평가`는 완료 처리하지 않고 다음 항목으로 이동한다. 이전 항목은 다시 열어 수정할 수 있다.

완료된 평가를 수정하면 임시 저장 상태로 바뀌므로, 다시 평가 완료 버튼을 눌러야 한다.
네 기준을 합친 자동 채택 판정이나 다른 평가자의 답변은 평가 화면에 보여주지 않는다.
어려운 항목에는 UNCERTAIN을 사용할 수 있다. 완료는 모든 판정에 확신이 있다는 뜻이 아니다.

## 블라인드 범위와 자료 고정

자료는 `inputs.jsonl`의 문항과 `trajectories.jsonl`의 수정 전후 및 계획에서 가져온다.
채택/거절 여부로 고르지 않고, **생성된 모든 후보**를 포함한다. 후보 생성 전 실패해
`candidate=null`인 행만 제외하고 비공개 manifest에 이유를 기록한다. 잘못된 입력은 조용히
건너뛰지 않고 준비 단계에서 오류로 처리한다.

브라우저에 전달하는 항목은 허용 목록으로 새로 구성한다.

| 전달하는 정보 | 전달하지 않는 정보 |
|---|---|
| 문항, 원문, 수정문 | Kanana 점수, 자질, 점수 변화 |
| 수정 목표, 보존 조건 | 기존 RV 라벨·이유·채택 여부, 모델명 |
| 임의의 항목 ID, 현재 평가자의 답변 | 원본 sample_id, 반복 회차, 재시도 번호 |
| 현재 평가자에게 배정된 순서 | 예상 오류 유형·예상 정답, 다른 평가자의 답변 |

원문→수정문 관계는 판단에 필요하므로 유지한다. 독립적인 전체 글 A/B 선호 평가 기능은 아니다.
현재 파일럿과 같은 과제를 판단하도록 수정 목표와 보존 조건을 제공하므로, 목표 자체의 영향은 남는다.
블라인드화는 표본 선정의 대표성이나 정답의 객관성을 보장하지 않는다. 자료나 기존 결과를 이미
본 사람을 새 평가자로 지정해도 기억을 제거할 수 없으므로, 실제 연구에는 사전에 결과를 보지 않은
평가자를 배정해야 한다. 같은 글의 후속 후보에서 맥락을 알아볼 가능성도 있다.

사례 내용·배정 순서는 준비 시 SQLite에 고정된다. 원본 실행 폴더가 이후 바뀌어도 평가 내용은
바뀌지 않는다. 평가자별로 다른 난수 시드를 사용해 순서를 섞고 같은 평가자는 항상 같은 순서로
재개한다. 원본 연결표와 해시는 서버 측 비공개 manifest에만 보관한다.

## 저장, 복구, 내보내기

평가는 SQLite 트랜잭션으로 저장되고 서버를 재시작해도 유지된다. 임시 저장과 제출 모두 변경
이력이 남는다. 여러 창에서 같은 항목을 수정하면 먼저 저장한 버전을 보호하고 뒤의 저장에는
충돌 오류를 반환한다. 화면에 남은 메모를 복사한 뒤 항목을 다시 불러올 수 있다. 저장에 실패하면
이동을 막고 작성 내용을 화면에 유지한다. 아직 저장하지 않은 채 창을 닫으면 브라우저가 확인한다.

`내 평가 내보내기`는 로그인한 평가자의 현재 저장 내용만 JSONL로 다운로드한다. 임시 저장도
포함하며 `status=submitted`가 평가 완료 상태다. 예상 정답이나 원본 ID 연결표는 들어 있지 않다.

연구자가 전체 평가와 원본 연결표를 얻으려면 서버에서 다음 명령을 실행한다.

```bash
python scripts/run_pilot_review.py export \
  --study-dir experiments/results/human_review_study \
  --output-dir experiments/results/human_review_export_01
```

평가자별 `R1.jsonl`, `R2.jsonl` 등에 현재 저장 상태를 기록하고, `history.private.json`에는
이전 저장 이력을, `manifest.private.json`에는 원래 사례의 연결표를 기록한다.
내보낸 폴더도 기존 폴더를 덮어쓰지 않는다. 이 명령은 평가자 링크로 접근할 수 없다.
일치도나 RV 성능 집계는 아직 포함하지 않는다. 빈 사람 평가를 자동으로 채우지 않는다.

| 서버 파일 | 내용 |
|---|---|
| `review.sqlite3` | 고정된 평가 항목, 평가자별 배정, 현재 답변, 변경 이력 |
| `reviewers.private.json` | 평가자별 참여 코드. 평가자에게 파일 전체를 공유하지 않는다. |
| `manifest.private.json` | 원본 경로·해시, 항목 연결표, 준비 설정, 제외 사유 |

평가 폴더는 소유자만 접근하도록 만들고, SQLite와 비공개 JSON은 소유자 읽기·쓰기로 생성한다.
HTTP 서버는 정해진 정적 파일과 평가 API만 제공하며 이 파일들을 직접 내려주지 않는다.
서버 파일을 읽을 수 있는 연구자까지 차단하는 구조는 아니다.

## 코드와 검증

- `feak_tc/review/store.py`: 허용 목록 변환, 자료 고정, 평가자 인증, 저장 및 내보내기.
- `feak_tc/review/server.py`: 평가자별 API와 정적 화면. 모델 호출 기능 없음.
- `feak_tc/review/static/`: 한국어 비교·평가 화면. 외부 폰트/CDN/분석 스크립트 없음.
- `tests/test_human_review.py`: 숨은 정보 차단, 평가자 분리, 재시작 복구, 동시 수정 충돌,
  잘못된 제출 거절, 자료 고정, HTTP 경로 제한 및 내보내기 범위.

```bash
python -m pytest -q
```
