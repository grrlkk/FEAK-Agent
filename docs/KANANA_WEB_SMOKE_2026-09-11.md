사용자 요청에 따라 진단기는 기존 학습된 Kanana를 유지하고, 나머지 네 역할을 일반
`kakaocorp/kanana-1.5-8b-instruct-2505`로 통일했다. 신규 학습이나 외부 LLM API 호출은 없다.

## 실제 모델 실행

진단기 GPU 1 / 일반 Kanana GPU 2, 각각 4비트. 진단 `m=3`, feature와 BGE-M3는 CPU.
과제는 인권의 의미와 학교의 인권 존중 방법, 입력은 204자, 최대 2단계·단계별 후보 2개다.
각 실행의 원문·후보·원응답·실패는 로컬 결과 디렉터리에 그대로 남겨 두었다.

두 번째 실행에서 생성기에도 `PatchText` 스키마와 기존의 제한된 스키마 재시도를 적용했다.
잘못된 텍스트를 파싱 성공으로 꾸미거나 판정 조건을 완화하지 않았다. 진단→계획→생성→재진단→
두 축 RV→채택→경로 가드→복구→재계획→종료가 실제 Kanana 호출로 연결됨을 확인했다.

## 확인된 품질 한계

- 후보 A가 원문에 없는 ‘우리 학교의 알레르기 친구’ 사례를 실제 사실처럼 생성했고 RV는 보존을
  pass로 판정했다. 이 후보는 **편집량 및 NO_OP 비교**에서 거절됐다. RV가 날조를 검출한 것이 아니다.
- 후보 B는 RV 통과 후 채택됐지만 가드의 preservation=partial로 원문에 복구됐다.
  RV와 가드의 설명에는 실제 후보에 없는 1인칭 경험 언급이 있어, 복구가 올바른 판정이었다고
  주장할 수 없다. 가드 근거는 한국어 지시에도 영어로 반환됐다. UI는 원응답을 그대로 표시한다.
- 복구 후 Planner가 같은 action·span을 다시 제안해 controller가 중복 실패 계획으로 거절했다.
- 최종 글은 원문과 같다. 이 실행은 전체 제어 연결과 실패 보존을 검증한 것이며, 글쓰기 품질이나
  판정 정확도·최초성을 입증하지 않는다. 반복적인 프롬프트 튜닝·추가 학습은 이번 범위에 포함하지 않았다.

결과 위치: `experiments/results/web_runs/<실행 ID>/result.json` 및 같은 폴더의 이벤트·프로세스 로그.
로컬 입력·실험 결과·스크린샷·모델은 커밋하지 않는다. 실행 방법은
[로컬 에이전트 지침](TRAINING_FREE_AGENT.md#웹에서-실행-과정-보기)을 참고한다.
