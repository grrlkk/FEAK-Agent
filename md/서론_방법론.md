# 서론 정리 (Trajectory-level Revision Control)

> 핵심 한 줄: 기존 연구들이 좋은 글을 **생성·평가하는 부품**을 발전시켰다면,
> 본 연구는 FEAK의 측정 신호와 전문가 데이터를 이용해
> Writing Agent의 **반복 수정 경로 자체를 제어**하려는 연구다.

---

## X. 분야의 큰 흐름

- LLM 기반 글쓰기 시스템은 단순 초안 생성·단발 피드백을 넘어, 글쓰기 과정에 반복적으로 개입하는 **Writing Agent paradigm**으로 이동하고 있다.
- Gooding et al.은 글쓰기를 open-ended agent의 대표적 testbed로 본다.
  - 정답이 하나로 닫히지 않고, 가능한 수정 경로가 많으며, 좋은 수정의 기준이 글의 목적·독자·장르·저자 의도에 따라 달라지기 때문.
  - Gooding은 Writing Agent의 핵심을 **exploration → evaluation → goal alignment** 문제로 정리.

---

## Y. 본 연구가 자리 잡는 구체 영역

- 본 연구는 Writing Agent 전체가 아니라, 그중 **반복 수정 경로를 어떻게 제어할 것인가**에 초점.
- 좋은 글을 한 번 생성하는 문제가 아니라, agent가 매 step 판단해야 하는 문제이며 크게 셋으로 묶임:
  - **무엇을 고를 것인가**: add / delete / compress / restructure / stop 중 어떤 action을, 어디에
  - **그 수정이 좋았는가**: 선택한 action이 실제로 필요했고 근거가 있는가
  - **경로가 망가지지 않았는가**: 의도·문체를 해치지 않았는가, 이전보다 나빠진 부분은 없는가, 더 고칠지 멈출지
- 본 연구의 위치: **Open-ended Writing Agent의 trajectory-level revision control**
- 핵심은 **generation quality**가 아니라 **revision control quality**.

---

## Z. 기존 연구 흐름

Gooding 이후 Writing Agent 연구는 대체로 세 방향으로 발전.

### Z1. Action 선택과 planning 강화
- 대표: CRAFT, WriteHERE, SuperWriter
- revision을 더 명시적인 planning/search 문제로 다룸. LLM이 아무렇게나 수정하지 않도록 구조화된 계획·탐색을 넣음.

### Z2. External evaluation signal 강화
- 대표: Rationalize and Align, LitBench, APRES, FeedbackWriter
- LLM 자기평가가 불안정하다는 문제 → reward model, rubric, rationale, human verification 같은 평가 신호를 붙임.

### Z3. Intent, evidence, drift 문제 대응
- 대표: Intention-Tuning, DeepWriter, QRAFT, Beyond Single-shot Writing
- 반복 수정 중 의도·근거·핵심 내용이 흔들리는 문제 → intent conditioning, evidence grounding, fact-checking, multi-turn regression 분석.

> 이 분류는 각 논문이 한 문제만 다뤘다는 뜻이 아니라, 주로 강조한 해결 방향 기준.

---

## B. 기존 연구가 남긴 구체적 문제

기존 연구들은 planning(Z1)·evaluation(Z2)·grounding(Z3)을 **각각** 발전시켰다.
그러나 반복 수정에서 이 셋은 독립적으로 작동하지 않는다. **서로가 서로의 전제이기 때문이다.**

- step마다 그 수정이 좋았는지 검증할 수 없으면, 나빠진 수정을 되돌릴 근거도 없다.
- 나빠진 수정을 되돌릴 수 없으면, agent는 삭제·재구성처럼 위험하지만 필요한 action을 고를 수 없다. 잘못되면 복구가 안 되므로 안전한 add만 반복하게 된다(action bias).
- 거꾸로 action을 상태에 맞게 고르지 못하면, 검증과 복구는 매 step 뒷수습만 하게 된다.

즉 action 선택·step 검증·경로 제어는 **하나의 control loop 안에서만 제 기능을 한다.**
기존 연구가 셋을 따로 발전시킨 탓에, 각 부품은 좋아졌지만 *반복 수정 경로를 끝까지 끌고 가는 능력*은 비어 있다.

### B1. Planning은 있지만, state-conditioned action policy가 부족
- CRAFT, WriteHERE, SuperWriter는 planning/search를 강화했으나, 이는 큰 구조를 잡거나 가능한 수정 경로를 탐색하는 데 가깝다.
- 남는 질문: 지금 이 글에 추가가 맞나 삭제가 맞나 / 문장 수정인가 문단 재구성인가 / 사용자 목표와 현재 상태를 고려한 우선 action / stop이 나은 시점.
- 이 기준이 없으면 action 선택이 안전한 쪽으로 쏠린다(복구 안전망이 없으니 add·보강 편향 = action bias).
- **핵심 차이: 구조를 계획하는 것과, 지금 이 순간 어떤 수정 action을 선택하는 것은 다른 문제다.**

### B2. 평가 신호는 있지만, step-level action utility 평가가 부족
- Rationalize and Align, LitBench, APRES, FeedbackWriter는 평가 신호를 강화했으나, 주로 *최종 결과* 평가(최종 글이 좋은가 / 둘 중 선호 / 전체 story·paper / AI suggestion 채택 여부).
- 본 연구가 보려는 것은 더 작은 단위: 이번 step의 action이 필요했나 / target issue를 해결했나 / 다음 경로에 기여했나 / 점수는 올랐지만 의미·의도를 해치지 않았나 / 이전에 좋아진 부분을 다시 망가뜨리지 않았나.
- 이 step-level 검증이 없으면 B3의 복구·종료 판단 자체가 근거를 잃는다(무엇이 나빠졌는지 step 단위로 재야 되돌릴지 정한다).
- **핵심 차이: 좋은 최종 결과를 고르는 것과, 좋은 수정 action을 고르는 것은 다른 문제다.**

### B3. Drift를 줄이려는 시도는 있지만, drift를 통제·복구·종료하는 구조가 부족
- Intention-Tuning, DeepWriter, QRAFT, Beyond Single-shot Writing은 intent·evidence·drift를 다뤘으나, 주로 *예방*(intent 반영, evidence grounding, fact-checking, regression 분석).
- 반복 수정에는 *발생 이후*가 필요: drift 감지 / 어느 step에서 생겼는지 추적 / 잘못된 수정 복구 / 필요한 부분만 minimal edit / 더 고치면 위험할 때 stop.
- **핵심 차이: drift를 줄이려는 것과, drift가 생겼을 때 수정 경로를 제어하는 것은 다른 문제다.**

### B 한 문장 정리
> 기존 Writing Agent 연구들은 planning·evaluation·grounding을 각각 발전시켰지만, 이 셋은 서로의 전제이므로 분리된 채로는 반복 수정 경로를 제어하지 못한다. 즉 **action 선택·step 검증·경로 제어가 하나의 control loop로 묶일 때 비로소** trajectory-level control이 가능해진다.

## W. 본 연구의 방향

- B가 요구하는 control loop를 만들려면, agent가 매 step 판단 근거로 삼을 신호가 두 조건을 만족해야 한다.
  - **정량적**일 것 — step 간 비교(좋아졌나/나빠졌나)가 가능하도록.
  - **검증 가능**할 것 — 왜 멈췄는지·되돌렸는지 감사(audit)할 수 있도록.
  - LLM 자기평가만으로는 이 둘 다 불안정하다(B2의 문제).
- 한국어 글쓰기에서 이 조건을 이미 만족하는 신호가 **FEAK**다.
  - FEAK는 글 상태를 rubric score, linguistic feature, elite benchmark gap, evidence sheet로 정량화하며, 모든 피드백이 이 측정값으로 역추적된다.
  - FEAK에서는 이 신호가 *한 번의* 근거 있는 피드백 생성에 쓰였으나, 같은 신호는 *매 step* agent의 판단 근거로 쓰일 수 있다.
- 본 연구는 이 신호를 반복 수정 과정의 control signal로 재구성한다:
  - **action 선택의 기준** (B1)
  - **step 검증의 기준** (B2)
  - **경로 진전·drift 추적의 기준** (B3)
  - **복구·종료의 기준** (B3)
- 여기에 보유한 AI-Hub 데이터를 활용한다.
  - 한 건 = (글, morpheme feature, 8 rubric별 평가자 2인 점수, rubric별 전문가 피드백, 채점 기준).
  - 사람 점수·피드백을 라벨의 *정답 근거*로 삼아, 채점 모델 자기참조(순환)를 피한다.

### W 한 문장 정리
> 본 연구는 FEAK식 정량 진단 신호와 전문가 데이터를 활용하여, open-ended Writing Agent가 반복 수정 과정에서 **무엇을 고치고, 무엇을 버리고, 언제 멈출지** 판단하도록 돕는 trajectory-level control 연구이다.

# 방법론 (경로 중심 + Feature-Grounded Process Reward)

> 한 줄: agent가 매 step 글을 수정하며 **경로가 좋은 방향으로 진전하는지 평가**하고,
> 진전하지 않으면 받지 않고, 더 나아질 게 없으면 **멈춘다(stopping)**.
> 진전 평가의 핵심은 **학습된 Process Reward Model(PRM)** 이며,
> 본 연구의 novelty는 **FEAK의 정량 feature로 PRM 학습 라벨의 노이즈를 보정**하는 데 있다.

---

## 1. 문제 정의 (MDP)

- 반복 수정 = 매 step 상태 보고 행동 고르는 순차적 결정 → MDP $(\mathcal{S}, \mathcal{A}, \mathcal{T}, R)$
  - **State**: 현재 글의 진단 신호(rubric·feature·elite gap) + 수정 이력(경로) + 원문 의도
  - **Action**: 추가 / 삭제 / 압축 / 재구성 / 종료
  - **Reward**: 각 수정의 **경로 진전 기여도** — 단순 step 점수가 아니라 "좋은 글로 가까워지는 경로인가"

## 2. 전체 동작 (한 step)

1. **관측**: 현재 글 → 채점 모델 진단 (rubric·feature)
2. **후보 생성**: LLM이 수정 후보 생성 (action별로 펼침)
3. **진전 평가 (PRM)**: 각 후보가 경로를 좋은 방향으로 진전시키는지 PRM이 채점 ← 핵심 모듈
   - 단순 "점수 올랐나"가 아니라 "좋은 글 분포로 가까워졌나 + 의도 보존했나"
4. **경로 제어**:
   - 진전하는 후보 채택
   - 어느 후보도 진전 못 시키면 받지 않음(복구 = 부산물)
   - 진전 폭이 작아지거나 더 고치면 위험 → **멈춤(stopping)**
- 경로가 수렴(stopping)할 때까지 반복

## 3. 서론(B)과의 대응

| 서론 문제 | 방법론 해결 |
|---|---|
| B1 (state-conditioned action 기준 부재) | 후보를 펼치고 PRM 진전 평가로 선택 → 상태 의존적 action 결정 |
| B2 (step-level utility 평가 부재) | PRM이 매 step 수정의 경로 진전 기여를 판정 |
| B3 (drift 추적·복구·종료 부재) | 진전 안 하는 수정 복구 + 위험 시 stopping |
| (통합) 셋이 따로 논다 | 위 셋을 하나의 경로 제어 loop로 통합 (서론 B의 핵심 주장) |

## 4. 핵심 novelty — Feature-Grounded Process Reward Model

### 4.1 왜 PRM이 필요한가 (경로 중심이라 정당)
- step 하나의 점수 상승만 보면, 점수는 오르나 의도·문체·타 rubric을 해치는 수정(reward hacking)·과수정을 거를 수 없다.
- 경로 전체의 진전을 보려면 단순 점수차로 부족 → 경로 진전을 평가하는 **학습된 PRM**이 필요.

### 4.2 PRM 라벨링의 표준과 그 약점
- PRM 학습의 표준은 **MC rollout**: 어떤 수정에서 출발해 끝까지 여러 번 진행 → 좋게 끝나는 비율로 그 step에 점수(라벨) 부여.
- 공인된 약점: MC 라벨은 **노이즈가 크고** 한쪽으로 쏠린다(수학·코드처럼 중간 step의 좋고 나쁨을 직접 못 봐서 끝까지 가본 결과로 추정해야 하므로).

### 4.3 본 연구의 보정 (novelty)
- 글쓰기는 다르다 — 매 step **FEAK의 dense한 정량 feature**로 "좋은 방향으로 갔는지"를 직접 측정할 수 있다.
- 따라서 **MC rollout의 outcome 신호(sparse·노이즈) + FEAK feature의 step 신호(dense·정확)** 를 결합해 라벨 노이즈를 보정한다.
- 핵심 주장: **"PRM 라벨의 노이즈를, 도메인 정량 신호(FEAK)로 줄인다."** dense signal이 없는 일반 글쓰기 agent는 못 하는, FEAK가 있어야만 가능한 기여.

### 4.4 라벨의 정답 근거 (순환 방지)
- 보정·라벨의 정답 근거는 **사람 신호에 grounding** — 채점 모델 자기참조 방지.
  - AI-Hub 4만 건: (feature, 사람 점수) 쌍 → "좋은 방향" 정의.
  - 같은 주제 저점수 글 vs 고점수 글의 feature 차이 = 진전 방향.
- positive: 진전 방향으로 간 수정 / negative: 점수만 올리고 의도·타 rubric 훼손(합성).

## 5. PRM 입출력

- 입력: (수정 전 feature, 수정 후 feature, action) [+ 경로 context]
- 출력: 경로 진전 기여도 점수
- 모델: 경량 (feature 벡터 입력) — 거대 LLM 불필요, GPU 부담 작음

## 6. 구현 단계

- **Stage 0**: 채점 모델 함수화 (글 → feature·rubric)
- **Stage 1**: 방향 신호 모델 (feature → 사람 점수) — 보정의 기준점
- **Stage A (먼저 확인)**: ① 단순 점수차가 reward hacking/과수정을 일으키나(→ PRM 필요성), ② MC 라벨이 실제로 노이즈가 큰가(→ 보정 필요성). 둘 다 본 연구 motivation.
- **Stage 2**: loop로 수정 경로(rollout) 생성
- **Stage 3**: Feature-Grounded PRM 학습 (MC 라벨 + FEAK 보정)
- **Stage 4**: loop 완성 + ablation

## 7. 평가

- **품질**: 수정 전→후 FEAK 점수, baseline 대비 (FEAK 1회 / 반복 FEAK / LLM self-refine / 제안)
- **경로 제어(핵심)**: 회귀율, 과수정 방지, oracle 대비 stopping 시점 적절성
- **PRM·보정 타당성(novelty 검증)**:
  - 보정 라벨 vs 비보정(MC만) 라벨 → 사람 평가 대비 어느 쪽이 정확한가 (← novelty 증명의 핵심)
  - PRM 판정 일관성 vs 평가자 2인 일치도(inter-rater)
- 소규모 human eval (FEAK 방식)

## 8. 범위 밖 (future work)

- policy 직접 학습(SFT/DPO/RL): A6000 환경이면 kanana-8B DPO로 확장 가능하나, 본 연구는 진전 평가 기반 value 방식으로 한정. 학습된 PRM을 reward로 policy를 학습하는 것은 차기 과제.
- 새 평가 프로토콜 정식화.

## (메모) 정합성 점검 + 남은 검증

- **서론 정합성**: B1/B2/B3 + 통합을 방법론이 1:1로 받음. 메인은 진전 평가 + stopping, rollback은 부산물. ✅
- **novelty**: "표준 PRM 적용"을 넘어 **Feature-Grounded PRM(라벨 노이즈 보정)** 으로 method novelty 확보. FEAK 정량 feature가 있어야만 가능 → "왜 우리만 가능한가" 명확.
- **남은 검증(종이로 못 푸는 부분)**:
  1. 단순 점수차가 hacking/과수정을 일으키는가 (→ PRM 필요성)
  2. MC 라벨이 실제로 노이즈가 큰가 (→ 보정 필요성, ②의 전제)
  3. FEAK 보정이 라벨을 실제로 개선하는가 (→ novelty 증명)
- 위 3개는 Stage A·Stage 4 실험으로만 답이 나옴. 특히 2번은 ②의 존재 이유라 가장 먼저 확인.
