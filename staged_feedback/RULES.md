# staged_feedback 규칙·검사 목록

2026-10-16 변경. 범위는 `staged_feedback/` 실행 경로와 여기서 재사용하는 native 어댑터의 계약이다. 다른 VERAK 실험의 규칙은 바꾸지 않았다.

최신 사용자 지시에 따라 수정 에이전트가 **수정한 글 전체**를 반환한다. 코드는 복원된 수정본을 그대로 저장한다. 글의 품질·형식·수정 범위를 이유로 거부하거나 이전 글로 되돌리는 검증기는 없다. 아래의 ‘유지’에는 실험 비용, 표본, 파일 보존, 응답을 읽기 위한 형식 조건도 빠짐없이 구분했다.

## 변경 시점의 근거

- A: `d9885ab`, 2026-10-16 11:31 KST. staged_feedback 최초 구현. 당시 세부 규칙의 도입 이유는 코드·프롬프트·README에서 추론한 목적이며, 모두 사용자의 명시적 요구였다는 뜻은 아니다.
- B: `520185a`, 11:38. 로컬 장르 메타데이터, 재시도 사이의 비용 원장 공유.

- D: `cd947a9` / PR121 병합 `74c922d`, 12:49–12:58. 사용자가 요청한 학생 과제 선분리, 원문 검사, 이번 턴 이슈 참조, 과제 중복 제거.
- E: `c5da98c`, 12:55. 빈 턴 재배정을 해결로 잘못 집계한 보고 수정.
- F: 이번 변경. 사용자 ‘코드 기반 검증기 제거’, 전체 글 출력, 관찰만 기록, 총괄 직접 검토, 고정 피드백 상한 제거 요청. 실행 시점은 ‘구현 검증 후 같은 6편 바로 재실행, $3 상한’으로 확인됨.

첫 재실행의 설명문 검토에서 ‘다음 2턴 계속’과 `turn_budget=1`이 함께 나왔다. 이에 검토 프롬프트에 **turn_budget은 남은 횟수가 아니라 전체 실행의 최종 턴 번호**임을 예시로 명확히 했다. 코드 검증·재시도 관문을 추가하지 않았다. 오프라인 확인에서 찾은 문장 시작 삽입, 동일 문장 중 한 개 삭제, 같은 이슈의 여러 대상 인용도 관찰에 빠짐없이 포함하도록 보완했다.

해당 설명문의 재시도에서는 검토가 다음 턴의 single_pass를 계획했는데 코드가 현재 턴을 그 마지막 턴으로 취급해 조기 종료했다. 이를 고쳐 **진행 중 single_pass 전환은 다음 한 턴**, 초기 single_pass 선택은 처음부터 한 턴으로 실행한다. 검토가 이미 끝난 턴의 전략을 소급 변경하지 않는다. 최초 두 시도는 보존하고 해당 한 편만 같은 비용 원장에서 재확인한다.

## 해석 시 주의할 점

- ‘거부 0건’은 새 검증기가 모든 수정을 승인했다는 뜻이 아니다. 거부 기능을 없앴다.
- 새 실행의 ‘원문 테스트 없음’은 통과 이슈가 0개라는 뜻이 아니다. 해당 측정을 제거했다.
- ‘해결’은 총괄의 판단이다. 코드 통과나 사람의 품질 평가로 해석하지 않는다.
- 관찰용 표시는 문장·단어 정렬에서 얻는 사실 후보다. 삭제/전면 재서술, 타당한 분할/피드백 밖 삽입을 의미 수준에서 구별하지 않는다.
- 테스트 코드(`tests/`)는 이 소프트웨어가 요청대로 기록·전달하는지 확인한다. 학생 글을 검사하는 실행 도구는 제거했다.
