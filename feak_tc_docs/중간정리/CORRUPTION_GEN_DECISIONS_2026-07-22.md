# Corruption 생성 — 운영 결정 기록 (2026-07-22)

`docs/SPEC_CORRUPTION_TVM.md`의 설계(action 역연산, 재측정 필수, GBM 먼저)는
그대로 따르고, 스펙이 비워둔 운영 파라미터를 사용자와 확정했다. 구현은 아직
시작 안 함 — 다음 작업자는 이 결정대로 진행하면 된다.

## 확정된 결정

1. **진행 순서**: 파일럿 50편 먼저 → 폐기율·GPU 시간·API 비용 실측 →
   파일럿 쌍으로 GBM 학습 확인 → 본 생성 스케일업.
2. **체인 설계**: 깊이 3 (x0→x1→x2→x3), 스텝당 corruption 연산자 1개,
   글당 체인 1개. 연산자는 5종에서 중복 없이 3개 무작위 샘플
   → 글당 선호쌍 C(4,2)=6개, action 라벨 분포 균등 유지.
3. **본 생성 규모**: 1,000편 (쌍 ~6,000, 재측정 ~4,000회). 파일럿 실측 후
   재조정 가능. TVM 본학습용 증량은 GBM 결과 보고 결정.
4. **소스 선별** (`scripts/select_corruption_sources.py`, 시드 20260722):
   grader 2인 평균(척도 1~5) 질문별 상위 ~25%, 층화 추출, 길이·문장수 필터.
   - **중요 제약: kanana 채점기가 train.jsonl로 학습됨** (2026-07-22 확인).
     따라서 파일럿 50·본 생성 1,000은 train.jsonl에서 뽑되(채점기
     in-distribution — 측정 신뢰 유리, 단 암기 앵커링 리스크는 파일럿에서
     체크), **held-out 200은 test.jsonl(채점기 미학습)에서 분리** —
     "TVM이 채점기도 못 본 글에 일반화" 주장을 깨끗하게 유지.
   - Stage A 100편과 겹친 15편은 전 풀에서 제외. 세 풀 텍스트 상호 배타 확인.
   - 미결: valid.jsonl이 채점기 학습 중 체크포인트 선택에 쓰였는지 사용자
     확인 필요 (안 쓰였으면 여분 청정 풀로 활용 가능).
5. **실행 방식**: LLM(gpt-4o-mini) 위주 + 규칙 보조 (스펙 리스크 §6).
   Stage A patcher처럼 span 고정으로 "어느 문장을 어떻게 뭉갰는지" 기록
   → 역방향 action의 target_span 라벨 확보.
6. **validity 정책**: 구조 가드(문장 파편, essay_min_ratio)는 적용,
   의미보존(gp)·정의 문장 가드는 의도적 훼손이므로 미적용.
7. **라벨링 정책 (2026-07-23 파일럿 후 개정)**: 선호 라벨은 채점기 하락
   증명이 아니라 **체인 구성 순서**(단조 훼손이므로 by construction 유효)가
   담당한다. 채점기는 **역효과 veto만**: 전체 점수가 노이즈 상한(0.225,
   m=10) 이상 *좋아진* 스텝만 폐기 (그런 쌍은 라벨이 반전되므로).
   - 근거: v1 파일럿에서 "의도 축 0.3 하락 증명" 게이트는 폐기율 74~88%
     (문장 1개 훼손이 에세이 단위 채점 노이즈 아래라서). test 글 대조
     실험으로 암기 앵커링 아님을 확인. 게이트 반전 후 폐기율 0~17%,
     쌍 62→231개.
   - 실측 누적 하락은 버리지 않고 **쌍별 confidence**로 기록 (v1 기준
     27%가 채점기 확인 쌍) → margin/가중치로 사용.
8. **난이도 혼합 (2026-07-23)**: v1(스텝당 문장 1개 = 미묘한 차이,
   어려운 쌍)과 v2(스텝당 다문장 = 큰 차이, 쉬운 쌍) 체인을 **둘 다**
   학습 데이터로 사용. 배포 시 TVM이 평가하는 대상은 문장 1개 수정
   transition이므로 어려운 쌍이 분포 정합을 담당하고, 쉬운 쌍은 순서의
   뼈대와 큰 margin을 담당한다.

## TVM 학습 테크닉 인벤토리 (스펙 §4 보강)

corruption 특성을 loss/데이터 구성에 반영하는 장치들 — 논문 방법론의
기술적 기여 후보:

1. **Δstage margin BT**: margin을 사람 확신도 라벨 없이 corruption
   단계차에서 획득 (Llama 2 RM margin의 label-free 변형).
2. **측정 기반 confidence 가중**: 채점기 실측 누적 하락이 노이즈 이상인
   쌍(확인 쌍)에 가중치/추가 margin, 노이즈 안쪽 쌍은 순서 라벨만으로
   약한 가중 — 라벨 노이즈에 강건한 BT.
3. **역효과 veto**: 채점기를 라벨 생성이 아니라 라벨 오류 제거에만 사용
   (denoising 역할 분리).
4. **난이도 혼합/커리큘럼**: intensity 축(v1 미묘/v2 강한)으로 쉬운 쌍과
   어려운 쌍을 명시적으로 혼합. 스펙의 2단계 커리큘럼(Stage1 corruption
   대량 → Stage2 사람 쌍)과 직교하는 축.
5. **순방향 hard negative**: 여담삽입 스텝은 "나쁜 ADD"로도 라벨링 —
   같은 action_type 안에서 좋은/나쁜 실행 구분 학습.
6. **edit-크기 편향 통제**: 혼합 데이터가 "많이 바뀌면 나쁨" 지름길
   학습을 방지하는지 ablation으로 확인 (v1-only vs v2-only vs 혼합).
7. (스펙 기존) 1 epoch 엄수, 출력 zero-mean 정규화, GBM 선행 검증.

## 연산자 ↔ 역방향 action ↔ 주 하락 예상 축

| corruption (순방향) | 역방향 action | 주 하락 예상 rubric |
|---|---|---|
| 구체 사례·근거 삭제 | ADD_DETAIL | content_2(설명구체성), content_1 |
| 주제 무관 문장 삽입 | DELETE_OR_FOCUS | content_3(설명적절성), organization_2(글통일성) |
| 반복·장황화 주입 | COMPRESS | 길이·반복 feature 계열 (rubric 축은 파일럿에서 확인) |
| 문장 순서 섞기·접속 제거 | RESTRUCTURE | organization_1(문장연결성) |
| 종결어미 단일화·어휘 반복 | STYLE_REFINE | expression_1·2(어휘·어법적절성) |

예상 축이 실측과 다르면 표를 갱신할 것 (스펙 §2 ③: "뭉갰으니 나빠졌겠지" 가정 금지).

## 파일럿 결과 (2026-07-23, 50편 × v1/v2 두 강도)

로그: `experiments/results/corruption_pilot_50{,_v2}_{chains,measured_gpu*,summary}.jsonl/json`

| | v1 (문장 1개/스텝) | v2 (다문장/스텝) |
|---|---:|---:|
| 체인 ok/partial/failed | 42/7/1 | 41/6/3 |
| 폐기율 (역효과 veto) | 0~17% | 0~15% |
| 선호쌍 | 231 | 219 |
| 채점기 확인 쌍 (누적하락≥0.225) | 27% | 32% |
| 측정 시간 | 47.3s/상태 (m=10) | 동일 |

- **합계 450쌍 / 50편** (글당 9쌍, 두 강도 혼합). 암기 체크: kanana x0 vs
  사람 grader pearson r≈0.55~0.57 (극단적 암기 아님).
- v2 강화 효과는 내용 계열에서 뚜렷: DROP_DETAIL 의도축 +0.13→+0.35,
  INSERT_OFFTOPIC +0.21→+0.38 (노이즈 상한 초과). 반면 SHUFFLE_FLOW(+0.09),
  FLATTEN_STYLE(+0.15), VERBOSE(+0.02)는 다문장 훼손에도 rubric 반응 미약
  — **kanana rubric은 내용 훼손에 민감하고 흐름·문체 훼손에 둔감**하다는
  실측. RESTRUCTURE/STYLE_REFINE/COMPRESS 계열 쌍은 순서 라벨과 feature
  채널 의존이 크므로, 사람 정렬 검증(소스 ③)에서 이 세 action을 중점
  확인할 것.
- **판정: 파이프라인 검증 완료, 본 생성 진입 가능.** 비용 실측: 상태당
  47s(m=10) → 1,000편 × 두 강도 = 상태 8,000개 ≈ GPU 3장 약 35시간.
  규모/강도 선택은 사용자 결정 사항.
