# FEAK-TC 진행 상황 보고 (2026.07)

## 슬라이드 1 — 제목

- 한국어 글쓰기 반복 수정 에이전트 FEAK-TC
- 진행 상황: 수정 파이프라인 품질 검증 및 개선
- 2026. 7. 20.

## 슬라이드 2 — 시스템 구성 (복습)

- 진단: 학습 완료된 채점기(Kanana-8B + LoRA)가 글의 8개 rubric 점수 산출, 약점 rubric 3개 선정
- 제안: LLM(GPT-4o-mini)이 약점별 수정 계획 생성 (5개 action 유형)
- 패치: 계획에 따라 원문에 국소 수정 적용
- 평가: 수정 전후 재채점으로 transition 지표 산출 (목표 향상도, 의미 보존도 등)
- 판정: 지표 기반으로 후보 1개 채택 또는 전량 거부

## 슬라이드 3 — 이번 기간 수행 내용

- 연속 점수(soft score) 기반 100건 베이스라인 구축 (7/16)
- 채택 결과 전수 질적 검토 및 결함 유형 분류 (7/17)
- 결함 원인별 개선 3종 구현 (7/17 ~ 7/19)
- 동일 입력 100건 반복 실험으로 개선 효과 정량 검증 (7/19 ~ 7/20)

## 슬라이드 4 — 베이스라인 결과와 문제 발견

- 100건 중 52건 수정 채택, 오류 0건으로 실행 자체는 안정
- 채택 52건 질적 검토 결과 최소 15건(29%)에서 결함 확인
  - 삭제 위치 오류: 지정 문장 대신 주제문 등 엉뚱한 문장 삭제 (12건 중 11건)
  - 통계 환각: 원문에 없는 수치·조사 결과 삽입 (3건)
  - 문장 중복: 압축문 삽입 후 원문 미삭제 (1건)
- 핵심 문제: 기존 지표가 결함을 전혀 감지하지 못함
  - 환각 3건 모두 의미 보존 점수 만점(1.0)으로 통과

## 슬라이드 5 — 원인 분석

- 패치 LLM이 수정 위치를 자유롭게 선택하는 구조가 근본 원인
  - 계획 단계에서 수정 대상 문장(target span)이 이미 지정됨에도
    패치 단계에서 LLM이 다른 위치를 반환해도 검증 없음
- 의미 보존 지표는 토큰 잔존율(글자 겹침) 기반
  - 정당한 바꿔쓰기를 감점, 문맥 붕괴는 미감지
- 환각·중복은 어떤 점수 지표로도 포착 불가능한 유형

## 슬라이드 6 — 개선 1: 수정 위치 고정

- 수정 위치를 코드가 문자 offset으로 고정, LLM은 대체 문장만 생성
- 삭제는 LLM 호출 없이 기계적으로 수행
  - 삭제로 접속어가 어색해진 경우만 다음 문장 1개를 최소 수선
- 효과: 위치 오류가 검출 대상이 아니라 구조적으로 불가능해짐
- 검증: 재실행에서 삭제 후보 100개 전수 위치 오류 0건

## 슬라이드 7 — 개선 2: 규칙 기반 가드 3종

- 원문에 없는 숫자·연도 삽입 검출 (환각 차단)
- "조사에 따르면" 등 신규 인용 표현 검출
- 근사 중복 문장 검출 (문자 bigram 이중 임계, 원문의 기존 반복은 허용)
- 기존 로그 후보 500개 소급 검증: 확인된 결함 4건 전부 검출, 채택분 오탐 0
- 재실행에서도 매회 10건 내외 차단 — 프롬프트 금지만으로는 환각이 계속
  발생함을 확인, 가드 필요성 입증

## 슬라이드 8 — 개선 3: 의미 유사도 지표 교체

- 후보 모델을 자체 라벨 데이터로 직접 평가
  - 질적 검토로 확정한 정상 수정 47건 vs 결함 수정 12건의 분리력(AUC) 측정
- 결과: BGE-M3 채택 (AUC 0.82, 기존 토큰 방식 0.76)
  - 고전 한국어 SBERT는 0.65로 기존 방식보다 열세
  - 원인: 최대 입력 128토큰 제한으로 에세이 후반부 수정 미반영
- 임계값도 새 지표 스케일에 맞게 재보정 (0.7 → 0.95)

## 슬라이드 9 — 검증: 동일 100건 3회 반복 실험

| 구분 | 베이스라인 (7/16) | 위치고정+가드 (7/19) | +BGE-M3 (7/20) |
|---|---|---|---|
| 채택 수 | 52 | 48 | 56 |
| 채택 중 결함 | 21 | 0 | 0 |
| 채택 의미보존 최솟값 | 0.73 | 0.73 | 0.96 |

- 채택 수를 유지하면서 검출 가능한 결함 21건 → 0건
- 압축(COMPRESS) 채택 7 → 12건: 글자 겹침 지표가 정당한 압축을
  부당하게 거부하던 문제 해소

## 슬라이드 10 — 결론 및 향후 계획

- 결론: 수정 파이프라인의 신뢰성 확보
  - 채택된 수정을 사람 검토 없이 학습 데이터로 쓸 수 있는 수준 도달
- 향후 계획
  - 제안 단계 개선: 질문 핵심어를 정의하는 문장이 삭제 대상으로
    선정되는 문제 수정
  - corruption 데이터 생성 착수 (TVM 학습용)
  - TVM 학습 → controller 통합 → 다단계 수정 평가
